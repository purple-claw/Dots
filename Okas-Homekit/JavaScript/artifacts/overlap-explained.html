    Every line, in plain English

    Try these three

    • Job takes 35 ms, spawn every 10 ms → peak is 4. New jobs arrive faster than old ones leave, so they pile up — but the pile has a ceiling.
    • Job takes 10 ms, spawn every 35 ms → peak drops to 1. Each job finishes long before the next one is born; nothing ever overlaps.
    • Job takes 100 ms, spawn every 10 ms → peak jumps to 10. Same 14 lines of code, ten times the memory held at once. Nothing in the code changed — only the two numbers on lines 9 and 13.

    Payoff

    Peak overlap ≈ ceil(job time ÷ spawn interval). With 35 ÷ 10 that is ceil(3.5) = 4. The real file never prints this, which is the quiet lesson: mxRng on line 8 is the only thing measuring it, and it is thrown away. Swap in a slower job and the same code silently holds 10, 20, 100 jobs in memory.

    A real Node run of an instrumented copy (same numbers) produced:

    t=11   start  → rng 1
t=21   start  → rng 2
t=31   start  → rng 3
t=41   start  → rng 4   ← peak, and it stays here
t=46   end    → rng 3

t=202  clearInterval     no more new jobs
t=209  end    → rng 2
t=219  end    → rng 1
t=229  end    → rng 0   mxRng = 4

    The two traps. First: setInterval counts 10 ms from the clock, never from when the previous job finished — so jobs overlap by design, not by bug. Second: wrk returns a promise that nobody awaits, so errors inside it would never reach your try/catch either.

    Quick check

    1. If line 13 became setInterval(wrk, 5), and the job still takes 35 ms, what is the new peak?

    Show answer

    ceil(35 ÷ 5) = 7. Halving the spawn interval roughly doubles the number of jobs alive at once — the plateau is set by the ratio, not by either number alone.

    2. Why does rng end at 0 instead of staying at 4?

    Show answer

    Every sleep(35) eventually resolves, and each resolution runs one line-10 callback that subtracts 1. Four pluses, four minuses. clearInterval only stops new jobs; the ones already sleeping still finish.

    3. What would happen if line 9 had no return?

    Show answer

    Nothing visible. setInterval ignores return values either way. The promise would still be created, so the count and the timing would be identical — the return is for humans, not for the timer.
